**Date:** 2026-07-25
**Branch:** `feature/v2.4-completion`
**Status:** approved (user), in implementation

Finishes the approved v2.4 plan (`~/.claude/plans/fuzzy-mixing-whale.md`). The report
package, `lib/` scan modules, adaptive targeting, evasion, and MITRE tagging already
landed. This spec covers the remaining phases plus the user's explicit emphases:

## Goals (priority order)

1. Rebuild the running UI: fix the broken spinner; TTY/`NO_COLOR` aware; aligned layout.
2. Make the HTML report more dynamic and ensure it shows exact, consistent information.
3. English README (single source of truth); document uninstall; fix `install.sh`/`uninstall.sh`.

## A. `lib/ui.sh` — running UI

New module owning terminal output, sourced **before** the scan modules (they call
`execute_scan`). Signature of `execute_scan(name, command, timeout, output, critical=false)`
is unchanged so the ~30 call sites need no edits.

- **Color/TTY init** (`ui_init`): `UI_TTY=1` iff `[ -t 1 ]`. Color on unless `NO_COLOR` set,
  `--no-color` passed, or non-TTY. When off, palette vars become empty strings.
- **Frames**: braille `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` when the locale is UTF-8, else ASCII `|/-\`.
- **`execute_scan` rewrite**: command runs backgrounded (`timeout T bash -c "$cmd" >out 2>&1 &`);
  the spinner loops **in the foreground while the real `cmd_pid` is alive**, `sleep 0.1`
  (10 fps), elapsed from `SECONDS`. This kills the `kill -0 $$` bug and ties animation to
  real completion. On non-TTY: no spinner, no `\r` — one `started`/`result` line each.
  Exit codes: `timeout`→124 = `⧖ timeout`; interrupted→`[STOP]`; empty output→`✗ no data`
  (return 1 if `critical`); else `✔ (N lines)`. Result rows aligned via visible-width padding.
- **`ui_phase_begin NAME [TOTAL]`**: prints an aligned `── NAME ──────` rule (replacing the
  mis-padded `╔══╗` boxes), resets the per-phase step counter, stores `TOTAL`. `execute_scan`
  shows `[NN/TT]` when TOTAL is known, else `[NN]`. Modules compute a mode-aware TOTAL next to
  their steps (single source; a comment marks "keep in sync").
- **Reduced dependencies**: `ui_rule`, `ui_disable_colors`, `ui_use_ascii` helpers.

`security` sources `ui.sh` first with an inline fallback (degraded but never crashes). The
old inline `execute_scan` in `security` is removed.

## B. Parallelism (Phase 2b)

`run_scan_group NAME cmd...` (in `parallel.sh`) sets `UI_PARALLEL=1`, runs via the existing
bounded `run_parallel` (`MAX_PARALLEL`), and each `execute_scan` inside prints atomic
`▷ started` / `✔ done` lines (no shared spinner → collision-safe). Wire the clearly-independent
groups: OSINT whois∥dns∥reverse-dns∥geo; web whatweb∥wafw00f∥ssl; network os∥snmp∥banner
**after** the port-scan gate (kept sequential). Sudo-gated nmap steps stay sequential to avoid
overlapping password prompts. Add tests to `test_parallel.sh`.

## C. `lib/config.sh` + `security config` + API keys (Phase 4/5)

- **`lib/config.sh`**: `config_dir` = `${XDG_CONFIG_HOME:-$HOME/.config}/security-scanner`,
  `config_file` = `$config_dir/config.env`. `load_config` sources it if present and warns if
  perms are looser than 600. `get_key NAME` echoes the value or empty. `set_key NAME VALUE`
  creates dir 0700, file 0600, upserts the line. `mask_key` for display.
- **`security config` subcommand** (parsed before the normal flow): `set NAME VALUE`,
  `list` (known keys + set/unset, masked), `path`, `edit`. Known keys: `SHODAN_API_KEY`,
  `CENSYS_API_ID`, `CENSYS_API_SECRET`, `HUNTER_API_KEY`, `VIRUSTOTAL_API_KEY`,
  `SECURITYTRAILS_API_KEY`.
- **Enrichers** in `osint.sh`, each gated on its key with a clean `[SKIP] … run: security config set`:
  - **Shodan**: `api.shodan.io/shodan/host/<ip>?key=` when keyed; **keyless passive fallback**
    `internetdb.shodan.io/<ip>` always attempted.
  - **hunter.io** (emails → append `osint/emails.txt`), **VirusTotal** (passive DNS/subdomains
    → append `osint/all_subdomains.txt`), **SecurityTrails** (subdomains), **Censys** (hosts).
  All via `curl`, timeboxed, output into existing `osint/*.txt` so current parsers ingest them.
  Live calls are **not verifiable on this Windows box** (no network/keys) — plumbing is unit
  tested (get/set/list, perms, skip logic); end-to-end is a Linux-box check.
- **`install.sh`**: new `configure_api_keys()` step — prompts per key, **each individually
  skippable (blank = skip)** and the whole step skippable up front; writes `config.env` (0600).
  Tells the user they can add keys later with `security config set`. `install_lib_modules` list
  gains `ui` and `config`.

## E. Phase 6 extras

- **`--resume <dir>`**: reuse an existing `redteam_*` dir; `execute_scan` skips a step whose
  output file already exists and is non-empty (records completion under `reports/.completed`).
- **`findings.json`**: `html_generator.py` also writes `reports/findings.json` (identical to the
  Python `assessment.json`). The Python model is the single machine-readable contract — no bash
  re-derivation (avoids drift). The redundant bash `generate_json_report` is retired in favor of
  the Python output (kept as a minimal fallback only if Python is unavailable).

## F. HTML report — dynamic + exact

Keep it self-contained/offline. Add to `app.js` (and small `render.py`/`styles.css` hooks):

- **Live "showing X of Y"** count that updates on search/filter; the `01 Findings` section meta
  reflects the filtered count.
- **Sort-direction arrows** (▲/▼) on the active sortable header.
- **Clickable statusline stats**: CRIT/HIGH/… toggle the matching severity filter; PORTS/
  SUBDOMAINS/ATT&CK scroll to their section.
- **Clear-filters** control shown only when a filter/search is active; `Esc` also clears.
- **`/`** focuses the search box.
- **Spine dimming** of non-active severities while a filter is on.
- **Gauge arc animates 0→score** on load (guarded by `prefers-reduced-motion`).
- **Correctness**: statusline, spine, and table counts all derive from the same
  `_severity_counts` — verified equal. Re-checked in-browser via Playwright over **http**
  (file:// is blocked) against a fixture `redteam_*` dir.

## Out-of-scope / caveats

- Live nmap scans and live API enrichment can only be end-to-end verified on a Linux/Kali box;
  this repo is developed on Windows. All such paths degrade gracefully and are unit-tested.
- No working exploits/brute-force/webshells/persistence are added — guidance only (unchanged).
